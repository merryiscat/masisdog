# masisdog 유즈케이스

> 킥오프 인터뷰 2부 산출물. 선택은 **케이스 → 스택 → 하네스** 한 방향으로 흐른다 —
> 여기선 하네스(스킬·MCP)를 정하지 않는다. 하네스는 케이스들의 "필요 기술"을 집계한 뒤 3부에서 고른다.
> **작성 중** — 배드 케이스·필요 기술에 초안 제안이 섞여 있다. 확인·수정하며 채운다.

## 공통 전제 A — 관찰·학습 인프라 (능동 케이스가 공유)

mas가 "먼저 알아서 제안"하려면 평소 내 행동을 관찰·기록하고 반복 패턴을 찾아야 한다.
- **관찰**: 앱 사용(UsageStats) + 위치(백그라운드) + 시간
- **학습**: 시간·위치·앱 상관에서 반복 루틴 마이닝
- 쓰는 케이스: UC-1, UC-2

## 공통 전제 B — 자율 행동 안전장치 (대신 행동하는 케이스가 공유)

mas가 대신 행동(결제·삭제·전화 거절)까지 하므로 되돌리기 어려운 행위엔 방벽이 필요하다.
- **확인 게이트**: 실행 전 "할까요?" 1회 (UC-1 결제, UC-4 삭제)
- **완전 자동이 불가피한 경우**(UC-3 운전 중): 사전 정책 + 사후 요약 통지로 대체
- (검토 필요) 지출 한도·허용 목록, 하루 1회 가드 등 — 케이스가 쌓이면 정책으로 뽑는다

## 공통 전제 C — 온디바이스 비전 (화면·이미지 이해)

UI 트리로 안 되는 걸 눈으로 본다. M0 벤치(온디바이스 단독 vs 하이브리드)가 이걸 좌우한다.
- 쓰는 케이스: UC-5(화면 인식), UC-4(이미지 분류), UC-2(앱 화면 폴백 읽기), UC-1(조작 실패 폴백)
- 온디바이스 우선(프로젝트 철학) → 무거우면 클라우드 비전 하이브리드

## 공통 전제 D — 거래·결제 감지 (돈 관련 케이스가 공유)

결제·거래가 일어나면 그 내역을 잡아내 파싱한다.
- **소스(확정)**: 결제/카드사 **알림 + 문자(SMS)** 를 읽어 파싱 (은행앱 조작 없이)
- 쓰는 케이스: UC-7(구독 감지), UC-8(지출 요약)

## UC-1. 아침 루틴 자동 주문 — 관찰·학습형, 결제까지 자율

**한 줄**: 특정 위치+시간대 도착 패턴을 mas가 스스로 학습 → 먼저 "늘 하던 거 할까요?" 물어봄 → "해" → 매머드 앱으로 아아(고정 주문) 결제까지 대신.

**해피 패스**
1. mas가 평소 앱·위치·시간을 관찰·기록한다
2. 반복 패턴 학습: "위치 X + 시간대 T 도착 → 매머드 아아 주문"
3. 다음날 위치 X, 시간대 T 도착 감지 (geofence + 시간 + 체류)
4. mas가 먼저 말 건다: "늘 하던 매머드 아아 주문할까요?"
5. 내가 "해"
6. mas가 매머드 앱 실행 → 저장된 고정 주문 그대로 재생 → 결제 완료
7. **끝 신호**: 앱 주문내역에 새 주문 + 픽업 안내가 뜬다

**배드 케이스 · 대응** _(초안 — 확인 요)_

| 어긋나는 지점 | 대응 |
|---|---|
| 위치 오차/GPS 튐 → 오트리거 | **막기**: geofence 반경+체류시간 조건, 애매하면 보류 |
| 패턴 오탐 (한두 번을 루틴 착각) | **막기**: 최소 반복 임계치(N일 연속) 넘어야 제안 |
| 무응답 ("해" 안 함) | **알리고 넘어감**: 일정 시간 뒤 조용히 취소 |
| 매머드 앱 UI 변경 → 조작 실패 | **알리고 정지** + 비전 폴백(공통 C) |
| 매장 마감 / 메뉴 품절 | **알리고 정지** |
| 결제 실패 (카드·잔액) | **알리고 정지** (되돌리기 없음) |
| 중복 주문 (이미 오늘 주문함) | **막기**: 하루 1회 가드 |

**필요 기술**: 공통 A · Geofencing+시간 트리거 · 능동 알림·응답 · 매머드 UI 조작(uiautomator2/mobile-mcp)→결제·고정 시퀀스 재생 · 결제 자율(수단 사전 등록)
**선결 과제**: 기기 ADB 연결 · 매머드 앱 계정+결제수단 등록 · 위치 권한(백그라운드)

## UC-2. 출퇴근 교통 코치 — 실시간, 타이밍

**한 줄**: 출퇴근 이동 중 mas가 버스·지하철 실시간 도착을 체크해 "지금 뛰면 탄다 / 여유 있다 / 곧 내릴 준비"를 때맞춰 알려줌.

**데이터 소스**: 공식 API 우선(가능하면), 안 되면 지도앱 화면 읽기 폴백. **버스+지하철 둘 다.**

**해피 패스**
1. 출퇴근 패턴 학습(위치·시간·이동) — **공통 A 재사용**
2. 이동 시작·정류장/역 방향 감지
3. 실시간 도착 조회: 공식 API(버스·지하철) → 없으면 지도앱(네이버/카카오) 화면 읽기
4. 도보 소요 vs 도착 시간 계산 → "뛰면 탐 / 여유 / 다음 차"
5. 때맞춰 알림
6. 탑승 후 목적지 접근 감지 → "곧 내릴 준비" (정거장 카운트/GPS)

**배드 케이스 · 대응** _(초안 — 확인 요)_

| 어긋나는 지점 | 대응 |
|---|---|
| 공식 API 다운/키 만료 | **폴백**: 지도앱 화면 읽기 → 그것도 실패 시 알리고 정지 |
| 폴백 경로 앱 UI 변경 | **알리고 정지** |
| 지하·실내 GPS 부정확(지하철) | 위치 대신 시간·수동 트리거 보조 |
| 노선/정류장 모호 | 1회 확인 후 학습에 저장 |
| 실시간 오차·지연 | "뛰면 탐" 임계를 보수적으로(버퍼) |

**필요 기술**: 공통 A · 공공 교통 실시간 API(+키) · 폴백 지도앱 조작·화면 읽기(공통 C) · 이동/활동 감지(Location, Activity Recognition) · 목적지 접근 감지 · 타이밍 정확한 알림
**선결 과제**: 공공 교통 API 키 확보(가능 여부 확인) · 위치 권한

## UC-3. 운전 중 자동 응답

**한 줄**: 운전 감지 시 걸려오는 전화는 끊고, 발신자에게 메신저/문자로 "운전 중, 나중에 연락"을 자동 응답. 메신저도 자동 응답.

**운전 감지**: 차 블루투스 연결(1순위) → GPS 속도(2순위).

**해피 패스**
1. 운전 시작 감지(블루투스 연결 → 없으면 속도)
2. 운전 모드 진입
3. 전화 옴 → **자동 거절** → 발신자에게 메신저/문자로 "운전 중, 나중에 연락"
4. 메신저·문자 옴 → 자동 응답 "운전 중"
5. 운전 종료 감지(블루투스 끊김/정지) → 모드 해제 + "그동안 온 연락 N건" 요약

**배드 케이스 · 대응** _(초안 — 확인 요)_

| 어긋나는 지점 | 대응 |
|---|---|
| 오탐(버스·지하철 타서 속도 남) | 블루투스 우선으로 완화, 속도만일 땐 보수적 임계 |
| 발신자가 메신저 없음 | SMS로 폴백 |
| 중요한 전화 놓침 | (검토) 반복 전화·화이트리스트는 예외 통지? |
| 운전 중 확인 불가 | 완전 자동 + 종료 후 요약으로 사후 통지(공통 B) |
| 모르는 번호·스팸에도 응답 나감 | (검토) 연락처 있는 사람만? |

**필요 기술**: 운전 감지(블루투스 상태, Activity Recognition/속도) · 통화 거절(Shizuku/telecom) · 발신번호 획득 · 메신저 RemoteInput·SMS 발송 · 운전 모드 상태머신
**선결 과제**: 전화 거절 권한(Shizuku 등) · 메신저별 RemoteInput 동작 확인

## UC-4. 사진·스크린샷 정리 — 분류 + 삭제는 확인

**한 줄**: 사진을 종류별로 분류하고, 지울 후보는 "이거 지울까?" 물어본 뒤에만 삭제.

**해피 패스**
1. 주기/용량 트리거로 갤러리 스캔(공유 저장소 접근)
2. **분류**: 스크린샷 / 중복·유사 / 영수증·문서 / 흐린·저품질 / 일반
3. 삭제 후보 선별(오래된 스크린샷·중복·흐린 것)
4. "이거(N장) 지울까?" 묶음 + 미리보기로 제안
5. 승인 → 삭제, 거절 → 유지
6. 분류 결과는 앨범/태그로 정리

**배드 케이스 · 대응** _(초안 — 확인 요)_

| 어긋나는 지점 | 대응 |
|---|---|
| 중요한 사진을 삭제 후보로 오분류 | **확인 게이트 필수(자율삭제 없음)** + 미리보기 |
| 중복 오판(비슷하나 다른 사진) | 보수적 유사도 임계 |
| 대량 스캔 성능·배터리 | 충전 중/유휴 시 백그라운드 실행 |
| 삭제 되돌리기 | MediaStore 휴지통(복구 가능) 경유, 즉시 영구삭제 금지 |

**필요 기술**: 공유 저장소 접근(MANAGE_EXTERNAL_STORAGE) · 이미지 분류(온디바이스 비전=공통 C, 중복은 해시/유사도) · 삭제(휴지통 API) · 트리거(주기/용량) · 묶음 미리보기 확인 UI
**선결 과제**: 저장소 관리 권한 · 온디바이스 이미지 분류 수단

## UC-5. 폰 기능 문의 — 역질문으로 명확화 후 대행 또는 안내

**한 줄**: "이거 어떻게 해?" 물으면 mas가 화면을 인식하고, **역질문으로** "직접 해줄까요/방법 알려줄까요?"·부족한 정보를 확인한 뒤 진행.

**특징**: 유일한 **반응형(내 발화로 시작)** + **비전 필요** 케이스. plan.md §5의 "스크린샷+비전 보조"가 폴백이 아니라 이 케이스의 본체(공통 C).

**해피 패스**
1. 내가 호출 + 질문("와이파이 어떻게 꺼?")
2. mas가 현재 화면 캡처·인식(UI 트리 우선 → 안 되면 비전)
3. **역질문으로 명확화**: "직접 꺼드릴까요, 방법을 알려드릴까요?" / 대상 모호하면 되물음
4. 답에 따라:
   - 대행 → 설정 화면까지 조작해 실행
   - 안내 → 단계별 방법 설명(+어디를 눌러야 하는지 화면 기준)
5. **끝 신호**: (대행) 상태 바뀜 확인 / (안내) 내가 따라 함

**배드 케이스 · 대응** _(초안 — 확인 요)_

| 어긋나는 지점 | 대응 |
|---|---|
| 화면 트리로 못 읽음(커스텀 UI) | 비전 폴백(공통 C) |
| 질문 모호("이거") | 역질문으로 대상 특정 |
| 대행 중 예상 못한 화면(팝업·권한요청) | 멈추고 물어봄 |
| 안내대로 했는데 화면이 다름(기종·버전차) | 다시 캡처해 재안내 |
| 위험 동작(초기화·결제·삭제) | 대행 전 반드시 확인(공통 B) |

**필요 기술**: 호출·대화(입력 + 역질문 대화 관리) · 화면 인식(UI 트리 + 비전 하이브리드=공통 C) · UI 조작(대행) · 단계 안내 · LLM(질문 이해·역질문 생성·화면 해석)
**호출 방식(확정)**: **음성** — "마시스독" 부르고 말로 질문. → 상시 음성 스택(wake word + 온디바이스 STT) 필요.

## UC-6. 수면 추적·기록

**한 줄**: mas가 내가 언제 자고 깼는지 추정·기록해 수면 시간을 보여줌. **기록만** — 넛지·차단 없음.

**자는 중 추정**: 폰 미사용 + 심야 시간대 + 충전 중 + 위치=집 조합.

**해피 패스**
1. 밤사이 폰 미사용·충전·정지 상태 관찰
2. 잠든 시각/깬 시각 추정(첫 미사용 구간 ~ 아침 첫 사용)
3. 매일 수면 시간 기록·누적
4. **끝 신호**: "어젯밤 6시간 20분" 같은 기록이 쌓여 보인다

**배드 케이스 · 대응** _(초안 — 확인 요)_

| 어긋나는 지점 | 대응 |
|---|---|
| 밤에 폰 봄 → 추정 어긋남 | 미사용 구간 기준 보정, 애매하면 낮은 신뢰도로 기록 |
| 낮잠·교대근무 | 시간대 고정 가정이 깨짐 → (검토) 수동 보정 |
| 폰 두고 다른 방에서 잠 | 감지 못 함 → 놓친 날로 표시 |

**필요 기술**: 공통 A(관찰 인프라 일부) · 폰 사용/화면·충전 상태 관찰 · 수면 구간 추정 로직 · 기록 저장
**선결 과제**: 사용 통계·상태 접근 권한

## UC-7. 구독·자동결제 감지

**한 줄**: 정기 결제를 감지해 "이 구독 계속 써? 요즘 안 쓰던데" 하고 정리를 도와줌.

**해피 패스**
1. 결제 알림·문자에서 정기 결제 감지(같은 가맹점·금액 반복) — **공통 D**
2. 구독 목록 구성 + 해당 앱 사용량(UsageStats) 대조
3. "안 쓰는데 계속 나가는" 구독 발견 → "이 구독 계속 써?" 제안
4. 해지 결정 → 앱 조작으로 해지 대행(UC 조작 재사용) 또는 방법 안내

**배드 케이스 · 대응** _(초안 — 확인 요)_

| 어긋나는 지점 | 대응 |
|---|---|
| 결제 문자 형식 제각각 → 파싱 실패 | 놓친 건 낮은 신뢰도로 표시 |
| 자주 가는 카페 등 반복 결제 오탐 | 가맹점 유형 구분 / 사용자 확인 |
| 웹 결제 구독(앱 없음) | 사용량 대조 불가 → 알림만 |
| 해지 대행 실패 | 방법 안내로 폴백 |

## UC-9. 약속 출발 알림

**한 줄**: 캘린더 약속의 시간·장소 + 실시간 교통을 계산해 "지금 나가야 안 늦어" 알림. (UC-2 교통 코치와 결합)

**해피 패스**
1. 캘린더에서 다가오는 약속(시간+장소) 읽음
2. 현재 위치 → 약속 장소 소요시간 조회(실시간 교통, **UC-2 데이터 재사용**)
3. 출발 시각 역산 = 약속 시간 − 이동 시간 − 여유
4. 출발 시각 되면 "지금 나가야 3시 약속 안 늦어" 알림
5. **끝 신호**: 제때 알림이 뜨고 내가 출발

**배드 케이스 · 대응** _(초안 — 확인 요)_

| 어긋나는 지점 | 대응 |
|---|---|
| 약속에 장소 없음/모호 | 물어봐 확인, 못 정하면 스킵 |
| 교통 급변(사고·지연) | 재계산해 재알림 |
| 캘린더 밖 약속 | 못 챙김(캘린더에 있는 것만) |
| 종일·온라인 약속 | 이동 불필요 → 제외 |

**필요 기술**: 캘린더 접근 · 실시간 경로·교통(UC-2 재사용) · 위치 · 출발시각 역산 · 알림
**선결 과제**: 캘린더 연동 · 위치 권한 (+ UC-2 교통 소스 공유)

## UC-13. 개인 지식 위키 — LLM이 유지 (RAG 아님)

**한 줄**: mas가 내 삶에서 알게 된 것을 LLM이 **위키(항목별 페이지)**로 정리·유지 → 물어보면 위키 읽고 답. 벡터 RAG가 아니라 **사람이 읽고 고칠 수 있는 구조적 지식베이스**.

**설계 의도**: 투명(내가 열어 수정) · 구조적(사람·장소·루틴·계정·선호별 페이지) · LLM이 갱신. **여러 케이스가 이 레이어에 사실을 쌓고 여기서 읽는다** — 3부에서 공통 전제로 승격 후보.

**해피 패스**
1. 관찰·대화·문자에서 "알아둘 사실" 추출(○○는 내 회사 / 매일 아침 매머드 아아)
2. LLM이 해당 위키 페이지에 반영·갱신(신규 생성/기존 수정)
3. 내가 자연어로 질문 → mas가 위키에서 찾아 답
4. 위키는 내가 직접 열어보고 고칠 수 있음

**배드 케이스 · 대응** _(초안 — 확인 요)_

| 어긋나는 지점 | 대응 |
|---|---|
| 잘못된 사실 기록 | 내가 수정(투명성 이점) + 출처·시각 함께 저장 |
| 민감정보(계좌·비번) 저장 | 온디바이스 암호화·접근 제한 |
| 위키 비대·중복 | 주기적 LLM 정리(머지) |
| 상충 정보(옛날↔최근) | 최신 우선 + 이력 보존 |

**필요 기술**: 온디바이스 LLM(사실 추출·페이지 작성·질의응답) · 구조적 저장(마크다운/DB) · 관찰 파이프라인(공통 A 등에서 피드) · (민감정보)암호화
**선결 과제**: 온디바이스 LLM 성능(M0)

## UC-16. 수신 문자 브리핑 — 전체 문자 중요도 분류·요약

**한 줄**: 결제 문자만이 아니라 **모든 수신 문자**(택배·지인·인증번호·공지·스팸)를 mas가 훑어 "중요한 것 N건 + 답장 필요한 것"으로 브리핑.

**UC-8과 구분(확정)**: UC-8(지출 요약)은 "결제 문자 → 금액 집계"(갈래 A). UC-16은 "전체 수신 문자 → 중요도 분류·요약·답장필요 판별"(갈래 B). 목적·처리가 달라 별 케이스. SMS 읽기 권한·소스는 UC-3과 공유.

**해피 패스**
1. 수신 문자 누적 관찰(공통 D의 SMS 소스 재사용, 결제 외 전체)
2. LLM이 각 문자 분류: 중요/일반/스팸·광고 + 답장 필요 여부
3. 트리거(아침 브리핑 / 부재중 몰아보기) 시 요약 제시: "안 읽은 12건 중 중요 3건 — ①택배 오늘 도착 ②○○ '내일 약속 시간?'(답장 필요) ③검진 예약 안내"
4. **끝 신호**: 내가 브리핑을 보고 답장 필요한 것만 처리

**배드 케이스 · 대응** _(초안 — 확인 요)_

| 어긋나는 지점 | 대응 |
|---|---|
| 중요 문자를 스팸으로 오분류 → 누락 | 보수적 분류, 애매하면 "중요"로 |
| 인증번호·민감정보 요약 노출 | 온디바이스 처리, 인증번호류는 요약에서 마스킹/제외 |
| 광고 과다로 신호 묻힘 | 스팸 필터 우선, 중요만 상단 |
| 답장 필요 오판 | 판별은 제안까지, 발송은 내가(자동발송 안 함) |

**필요 기술**: 공통 D의 SMS 소스(결제 외 전체) · LLM 중요도 분류·요약·답장필요 판별 · 트리거(아침/부재중) · (민감정보)마스킹
**선결 과제**: SMS 읽기 권한(UC-3와 공유)
