# masisdog 한눈에 (개요)

> 비개발자가 봐도 "이게 뭐고, 지금 어디까지 왔고, 어떻게 생겼는지" 잡히도록 쉬운 말로 적는다.
> 이 페이지가 위키의 입구다. 세부는 아래 링크로.

## 이름

- **프로젝트 이름**: `masisdog` (한글 표기 **마시스독** — 음성 호출어 "마시스독"과 같음)
- 저장소·폴더 이름도 `masisdog`로 통일됨.
- _(이름의 뜻·최종 확정은 사용자 확인 필요 — 지금은 저장소 이름 그대로 씀)_

## 한 줄로 뭐냐

**에이전트-퍼스트 폰.** 온디바이스 LLM 에이전트가 안드로이드 폰의 "관리자"로 상주하며
저장공간·네트워크·알림·화면을 관장하고, 재부팅 뒤에도 스스로 권한을 복구하며 생존한다. **개인용.**

## 지금 어디까지 왔나

기획·설계 단계다. **코드는 거의 없다.** 킥오프로 만든 것:
- 경로 결정(순정 앱 계층으로 시작 — 커스텀 OS 아님) → [plan.md](plan.md)
- 유즈케이스 16개 발굴 → [usecases.md](usecases.md)
- 필요 기술 집계·하네스 확정 → [stack.md](stack.md)

**단계**: 1단계 = PC로 폰을 원격 조작해 개념 검증 → 2단계 = 검증된 로직을 폰 안 앱으로 이식.

## 어떻게 생겼나 (구조 한눈에)

폰 에이전트가 굴러가려면 4개 층이 필요하다 (자세히는 [stack.md](stack.md)):

| 층 | 쉬운 설명 | 예 |
|---|---|---|
| ① 두뇌 | 폰 안에서 도는 작은 AI가 판단·대화·요약 | 온디바이스 LLM·비전·음성(STT) |
| ② 폰 제어 | 폰을 실제로 만지고 지켜보는 손·눈 | 화면 조작, 앱 사용 관찰, 알림·문자 읽기, 센서, 권한 |
| ③ 외부 연동 | 폰 밖 정보를 끌어옴 | 버스·지하철 API, 캘린더·연락처 |
| ④ 개발 도구 | 우리가 만들 때 쓰는 도구(제품 아님) | uv(파이썬), mobile-mcp, adb |

## 데이터는 어디 있나 — **DB 없음**

- masisdog엔 **서버도 데이터베이스(DB)도 없다.** 개인용이라 데이터는 **전부 폰 안**에 있다.
- 지식·메모는 두 군데: **이 위키(`docs/`, 사람이 읽는 마크다운)** + 2단계에선 **폰 온디바이스 저장**.
- ⚠️ **혼동 주의**: "DB 구조(Supabase 7테이블)"를 가진 건 **다른 프로젝트 Project Odin**이다. masisdog와 무관.
